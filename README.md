# Perishable inventory-routing under demand uncertainty

This repository studies a five-period, ten-store synthetic perishable inventory-routing problem with age-tracked FIFO inventory, a shared capacitated fleet, asymmetric holding/spoilage/stockout costs, and a Two-Phase decision-focused learning (DFL) candidate.

## Evidence status and scope

- Demand is generated by a hand-specified process in `data/generate_dataset.py`. No M5 observations are ingested and no empirical calibration is claimed.
- `main.tex` is the manuscript source of truth. `paper/manuscript.tex` and earlier PDFs/results are historical artifacts and do not represent the revised evidence.
- Files under `results/` from the original submission are preserved as legacy. The audited primary benchmark is stored in `results/revision2_final/`; exploratory smoke outputs and an interrupted run are separate and must not be cited.
- The operational policy comparator is a disclosed adaptation of Crama et al.'s UL_lambda rule. It is not a reproduction of their stochastic dynamic-programming/decomposition methods. The older routines labeled SAA, ALNS, MPC, or PIL are exploratory custom code and are not primary comparators.
- `results/revision2_robust_adaptation_exploratory/` contains a post-hoc finite-scenario robust plan-selection adaptation using validation residual paths. It is not a reproduction of He et al. (2024), all 300 candidate MILP calls used the construction fallback, and its comparisons are exploratory. It does not close the state-of-the-art comparator gate.
- The 50-epoch DFL fast path uses a vectorized polyhedral approximation for most minibatches and requests the integer oracle on selected minibatches in the final phase. This is not full-MILP-per-batch SPO+. The optimizer requests time-limited MILPs and may select a feasibility-checked construction fallback. Solver outputs report actual status and gap; optimality is not assumed.
- Jia et al. (2025)'s scenario predict-then-optimize method and He et al. (2024)'s robust perishable PIRP method are real, relevant published work, but neither source method is reproduced in this benchmark. The finite-scenario adaptation is separate and custom. The current comparison does not establish state-of-the-art coverage or resolve the rejection's comparator concern.

## Reproduce the revised benchmark

Use the repository's Python environment (Python 3.12.9) or install the packages in `requirements.txt`.

Generate 400 independent episodes (280 train, 60 validation, 60 test):

```powershell
.\.venv\Scripts\python.exe data\generate_dataset.py --output-dir data\revision2_final\processed --num-instances 400 --seed 20261028
```

Run the primary C1 benchmark with three DFL training seeds, 50 epochs, a requested 1% MILP gap, and a 0.5-second solver limit per plan:

```powershell
.\.venv\Scripts\python.exe -m src.experiments.run_revision_benchmark --data-dir data\revision2_final\processed --output-dir results\revision2_final --dfl-seeds 101,202,303 --dfl-epochs 50 --mip-rel-gap 0.01 --solver-time-limit-sec 0.5
```

The runner freezes the test feature set at episode start, tunes the UL_lambda policy using validation residuals only, evaluates every schedule with the same physical FIFO simulator, checks forecast-plan/simulator state parity, and writes a run manifest with input checksums and solver diagnostics.

The separately added robust adaptation is post hoc and exploratory. Reproduce it and audit its outputs with:

```powershell
.\.venv\Scripts\python.exe -m src.experiments.run_empirical_robust_comparator --data-dir data\revision2_final\processed --reference-dir results\revision2_final --output-dir results\revision2_robust_adaptation_exploratory --mip-rel-gap 0.01 --solver-time-limit-sec 0.5
.\.venv\Scripts\python.exe scripts\audit_robust_comparator.py results\revision2_robust_adaptation_exploratory
```

This run uses the same validation/test split and reports exploratory contrasts only. It does not overwrite the frozen primary outputs or reproduce He et al.'s source method.

Main outputs:

- `results/revision2_final/episode_metrics.csv`: paired episode-level cost, forecast, service, waste, route, and inventory outcomes.
- `results/revision2_final/summary.csv`: averages and episode-level spread, with training seeds averaged within each test episode.
- `results/revision2_final/paired_primary_tests.csv`: prespecified DFL versus LightGBM PTO and DFL versus UL_lambda-adaptation paired cost tests, bootstrap intervals, and Holm adjustment.
- `results/revision2_final/solver_diagnostics.csv` and `dfl_training_solver_diagnostics.csv`: solver status, bounds, gap, time, and heuristic fallback for evaluation and DFL training.
- `results/revision2_final/run_manifest.json`: data split, checksums, methods, settings, and environment.
- `results/revision2_final/validation_ul_lambda_tuning.csv`: validation-only policy grid.
- `results/revision2_robust_adaptation_exploratory/`: separate post-hoc empirical robust adaptation run, candidate diagnostics, solver outcomes, data hashes, and exploratory paired contrasts. It must not be merged into the prespecified primary test family.
- `results/revision2_robust_adaptation_exploratory/audit_report.json`: coverage, scenario-candidate count, cost reconciliation, FIFO parity, data hash, and source-scope checks; the audit passed.
- `scripts/audit_revision_results.py`: checks run completeness, episode coverage, cost accounting, FIFO parity, hashes, and paired-test outputs. The completed primary run passed; its report is `results/revision2_final/audit_report.json`.

The experiment's independent unit is the held-out episode, not the training seed. The 60-episode design targets a moderate paired effect; it does not guarantee adequate power for smaller effects.
