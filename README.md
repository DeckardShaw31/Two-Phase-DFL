# Perishable inventory routing: stock-age policies, stochastic lookahead and decision-focused learning

Replication package for the manuscript
*Replenishing perishables on shared delivery routes: Stock-age-based inventory policies, stochastic lookahead and decision-focused learning*.
It contains the code, configuration, random seeds and result files from which every table and figure of the manuscript is generated.

The study simulates a periodic-review perishable inventory-routing system (10 stores, 2 vehicles, fixed shelf life, FIFO issuing, lost sales, shelf capacity) under contextual demand and compares replenishment policies in closed loop with identical information:

| Family | Policies |
|---|---|
| Inventory rules, route second | BSP (base-stock), BSP-EW (base-stock + estimated waste), UL_lambda (Crama et al. 2018) |
| Learned rules | UL-DFL (proposed: decision-focused order-up-to levels); ablations NN-DFL (network orders directly) and NB-DFL (network sets its own order-up-to level) |
| Rolling-horizon PIRP MILP | LA-Mean, LA-Quantile, LA-Quantile2, LA-Robust (budgeted uncertainty), ScenPO-SS (Jia et al. 2025), LA-DFL (decision-focused planning targets) |
| Reference | PI (lookahead with realised demand) |

Synthetic demand is generated by a documented contextual negative-binomial model (`pirp/demand.py`); the real-data case uses the public FreshRetailNet-50K dataset (`pirp/fresh.py`).

## Contents

```
pirp/                     model, simulator, exact routing, MILPs, forecasts, policies, DFL, evaluation
experiments/              scripts that tune, train and evaluate the policies and write tables and figures
tests/                    unit tests (FIFO dynamics, exact TSP/CVRP, MILP feasibility, targets)
results_v2/               final study: one folder per configuration; base_fresh/ holds the fresh
                          base-case test episodes on which the primary hypotheses are tested
results/theory/           numerical verification of the structural results (Table 12)
results/<config>/         earlier round of the study on the same synthetic test episodes, and
results/base_proto/       the UL-DFL prototype on base-case test episodes 0-39; kept because the
                          manuscript discloses this earlier use of the test episodes (Section 5.5)
data/freshretailnet_raw/  dataset card of FreshRetailNet-50K; the data files are downloaded separately
manuscript_tables/        the tables (.tex) and figures (.pdf) exactly as used in the manuscript
```

Configuration folders and manuscript labels: `base` (Base), `net_c1` (Clustered), `net_rc1` (Mixed), `m2`, `m4` (shelf life), `pu10`, `pu40` (lost-sales penalty), `fleet_tight` (rho = 1.10), `fleet_loose` (rho = 1.60), `highvar` (High var.), `route3` (c^r = 3), `lifo` (30% LIFO), `fresh` (Real data).

Policy names in the result files: `UL` = UL_lambda, `PTO-Mean` = LA-Mean, `PTO-Q` = LA-Quantile, `PTO-Q2` = LA-Quantile2, `Robust` = LA-Robust, `DFL` = LA-DFL; `<policy>@s<k>` is the network of training seed k. `UL-coarse`, `UL-DFL-coarse` and `ScenPO-SS-bands` are the first versions of the rule tuning, of UL-DFL and of ScenPO-SS, and `UL-orig` is the rule exactly as published (all in Appendix B).

Each `results_v2/<config>/` folder contains

* `validation_tuning.csv` - closed-loop validation cost of every parameter setting;
* `*_training.csv` - training loss and closed-loop validation cost per epoch and seed of each learner;
* `test_episodes.csv` - per-episode outcomes of every policy (cost components, fill rate, waste, visits, solver statistics, store-level service);
* `test_summary.csv`, `paired_tests.csv` - means and paired episode-level tests (bootstrap CI, t-test, Wilcoxon, Holm);
* `*_policies.joblib` - the tuned parameters and trained networks;
* `manifest.json` - configuration, chosen parameters, seeds and software versions.

## Setup

The results were produced with Python 3.13.11 on Windows 11 (16-core Intel Core Ultra 9 285H, CPU only) with the package versions pinned in `requirements.txt`:

```bash
python -m venv .venv          # then activate it
pip install -r requirements.txt
```

Run every command from the package root. The real-data case needs the two data files of FreshRetailNet-50K (CC BY 4.0, Hugging Face dataset `Dingdong-Inc/FreshRetailNet-50K`) in `data/freshretailnet_raw/`, or in a folder named by the environment variable `FRESH_DIR`:

```bash
curl -L -o data/freshretailnet_raw/train.parquet https://huggingface.co/datasets/Dingdong-Inc/FreshRetailNet-50K/resolve/main/data/train.parquet
curl -L -o data/freshretailnet_raw/eval.parquet https://huggingface.co/datasets/Dingdong-Inc/FreshRetailNet-50K/resolve/main/data/eval.parquet
```

The files used in the study have 106,436,287 bytes (train, SHA-256 `6706832db892bbae4969c19d87e07975d2543d2ba7d7d4756360654785de5a3d`) and 8,440,124 bytes (eval, SHA-256 `1b118840664280c6b88bffc84c80ee1f54c05d911e354b7599e5da10995e960e`).

## Check the tables (minutes)

```bash
python -m pytest -q
python -m experiments.make_figures --results results_v2 --out regenerated
diff -r -x "*.pdf" -x "*.csv" regenerated manuscript_tables
```

`make_figures` reads only the result files. The `diff` lists no differences in `numbers_auto.tex` (every number the text quotes from the results) or in the generated tables; it reports only the two correction tables, which `analyze_uldfl.py` and `analyze_dfl.py` write (below).

## Reproduce the study

The full study takes about 30 hours of computation on the machine above. The steps must run in this order:

```bash
python -m experiments.verify_theory --out results/theory              # Table 12
bash experiments/run_chunk.sh 4 13 python     # tune, train and evaluate all 13 configurations, then the solver check
python -m experiments.retune_ul --results results_v2        # UL_lambda on the fine grid (validation only)
python -m experiments.retrain_uldfl --results results_v2    # UL-DFL trained from the re-tuned rule
python -m experiments.rerun_scenpo --results results_v2     # ScenPO-SS with the scenario set of Jia et al.
python -m experiments.run_nbdfl --results results_v2        # NB-DFL ablation
python -m experiments.ul_original --results results_v2      # the rule exactly as published
python -m experiments.fold_results --results results_v2     # fold all versions into test_episodes.csv
python -m experiments.fresh_test --results results_v2       # every base-case policy on fresh test episodes
python -m experiments.horizon_check --results results_v2    # LA-Quantile2 with 4- and 5-day horizons
mkdir -p regenerated/fresh
python -m experiments.rule_frontier --config base --results results_v2 --out regenerated
python -m experiments.rule_frontier --config base --fresh --results results_v2
python -m experiments.rule_frontier --config fresh --results results_v2
python -m experiments.analyze_uldfl --run results_v2/base --config base --out regenerated
python -m experiments.analyze_uldfl --run results_v2/fresh --config fresh --out regenerated/fresh
python -m experiments.analyze_dfl --run results_v2/base --out regenerated
python -m experiments.make_figures --results results_v2 --out regenerated
```

`run_chunk.sh [hours] [workers] [python]` works through the configurations in chunks of about `hours` hours (a configuration takes 1-2.6 hours with 12-15 worker processes) and can be called repeatedly; finished configurations are skipped. The steps after it take about five hours in total. Episodes and fitted forecasters are cached in `results/cache/` (about 360 MB), which the scripts create. Keep the computer awake during runs: HiGHS time limits count wall-clock time, and decisions solved while the machine sleeps can stop at the limit (check `nonoptimal` in `test_summary.csv`).

Other hardware, operating systems or library builds can change results in the last digits (multithreaded LightGBM and PyTorch). In addition, the closed-loop cost of the lookahead policies is sensitive to which of several near-optimal MILP plans the solver returns; Section 6.8 quantifies this noise floor.

## Notes on scope

* Lookahead MILPs are solved by HiGHS (via SciPy) to a 0.5% proven gap; routing binaries are kept for the implemented day and relaxed on later lookahead days, and day-0 routes are re-optimised exactly.
* ScenPO-SS uses the scenario set of Jia et al. (predicted deciles plus sampled scenarios, 20 in total), adapted to perishable FIFO dynamics with lost sales, with the shared LightGBM quantile forecasts instead of an MQ-RNN.
* The synthetic test episodes (seeds 9000+e) were also evaluated in an earlier round of the study (`results/`); the primary hypotheses are therefore tested on fresh base-case test episodes (seeds 20000+e, `results_v2/base_fresh/`).
